## Ground rules

1. **Upgrade `DataGrid`/`DataTable`, never fork it.** Every Figma part maps to
   an existing module or a prop on one first (CLAUDE.md decision ladder). A new
   file needs a line in this doc saying which existing module could not take it.
2. **Figma numbers, not eyeballing.** Every size, padding, radius and colour
   comes from the extracted spec (§ Spec) — colours through role tokens, never
   hex. Where Figma binds a variable that has no role, raise it in §Token gaps;
   do not inline the value.
3. **`DataTable`'s existing tests are the regression harness** — they must pass
   unmodified (backlog ground rule).
4. **Light and dark both**, every template.

## Definition of done — per item

An item is ticked only with all of:

- [ ] A Storybook story that renders it (the stories are the API docs).
- [ ] **Measured**: a Playwright check reads the rendered element's box and
      computed styles and matches the spec values (height, padding, gap,
      radius, border width, font size/weight/line-height) — ±0px for sizes,
      exact role for colour.
- [ ] **Compared**: story screenshot beside the Figma node screenshot, light
      and dark, differences listed and either fixed or accepted in writing.
- [ ] Unit/interaction test for any behaviour; axe clean.
- [ ] `npm run governance:ci` green and `npm run lint` clean.

## ~~Decision needed before §5~~ — Resolved 2026-10-30

Resolved by the hand-off §4.7 *Tree*: "`createExpandColumn` + indent, 24 per
level". That is the proposal below — sub-rows, no grouping engine, no treegrid.

**Hierarchy was cut on purpose** in `data-grid-backlog.md` §5 ("Tree rows" and
"Row grouping") because no consumer had hierarchical data. Two of the new
templates — *Grouped summary* and *Task list* — are hierarchical, so that cut
is reopened by design demand.

Proposed scope, to keep the original concern (treegrid keyboard map conflicts
with grid navigation) out: build both on the **existing sub-rows +
`createExpandColumn`**, with group values supplied by the consumer's data.
~~**No** TanStack grouping feature~~, **no** `role="treegrid"`. Revisit only if a
consumer needs client-side regrouping.

> **Partly reversed 2026-10-31.** "No grouping engine" held until 2026-10-31.

## Spec

Full extraction, one table per part: [`data-table-v3-spec.md`](data-table-v3-spec.md).

**How colour is wired.** The table consumes the Figma-named `--mds-color-*`
layer (generated from Figma, light + dark) one-to-one with the variables the
design binds — not `--role-*`, which approximates several of them (code's
`bg.row-hover` was Figma's *selected* colour). Precedent: `field.tsx`,
`bubble.tsx`. `pkg:css:selftest` confirms every reference resolves in the
published stylesheet.

**How density is wired.** `DENSITY_VARS` in `data-grid.tsx` sets `--dt-row-h`,
`--dt-header-h`, `--dt-inset-x/-y`, `--dt-gap`, `--dt-bar-inset-y` on the grid
root from Figma's `DENSITY` collection; every part reads those.

## Verification harness

Not yet a committed gate — run by hand each iteration:

1. `npm run storybook`, then for each template story × light/dark, a Playwright
   script reads box sizes, insets, fonts and colours of the shell, title bar,
   toolbar, header, rows and footer, and screenshots the shell at 1×.
2. The Figma node is exported at 1× (`get_screenshot`, maxDimension = frame
   width) and stacked above the code screenshot for review.
3. `npm test` (axe on every story), `npm run governance:ci`, `npm run lint`.

Promoting step 1 to a committed Playwright check is item 7.1 below.
