## Roles (Component API)

Roles are the stable interface that components consume via `getRoleColor('role.name')`. They resolve through semantic tokens to primitives. Components must never reference primitives or semantics directly.

<div style={{
  background: '#fff8ed',
  border: '1px solid #ffb700',
  borderRadius: 8,
  padding: '14px 16px',
  margin: '16px 0 28px',
  fontFamily: 'system-ui,sans-serif',
  fontSize: 12.5,
  color: '#5c4300',
  lineHeight: 1.6,
}}>
  <strong>Two unrelated meanings of "secondary" live on this page — easy to conflate.</strong> "Brand secondary" above (Sky Blue, <code>brandSecondary</code>) names the second color in Marsh's brand identity — an accent, not a text color. <code>text.secondary</code> below is a completely different axis: text-hierarchy secondary, i.e. de-emphasized body text — it resolves to a muted gray (<code>neutral700</code>), not to Sky Blue. Same word, two independent scales (brand-identity position vs. text-emphasis level) that happen to share a name. When you see "secondary" on a role, ask which axis it's on before assuming a color.
  <br /><br />
  <strong>Confirmed intentional (2026-09-15):</strong> Figma's own <code>Text &amp; icon/Secondary</code> variable actually resolves to Gold, not Sky Blue — so Figma's "secondary" collapses both axes into one word, and MDS's split naming is the deliberate, correct departure, not a bug to reconcile. See <code>docs/FIGMA_SEMANTIC_TOKEN_ASSESSMENT.md</code> for the full comparison.
</div>
