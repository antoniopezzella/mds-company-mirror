## Accessibility
- Keyboard: Native `<button>` semantics — activated with Enter or Space; receives focus via Tab order.
- Focus Ring: Relies on browser + MUI styles; must remain clearly visible (do not remove outline without a replacement). Future tokenization: `focus.ring.color`, `focus.ring.width`.
- Disabled State: Non-focusable and announces as disabled to assistive tech; avoid using `aria-disabled` on a native button.
- Tone Usage: `danger` should appear only for destructive / irreversible actions; `success` for confirmations.
- Color Contrast: Ensure label text passes WCAG AA against contained / outlined backgrounds (primary & danger meet contrast with white text; secondary relies on border + text color contrast).
- Motion: Keep hover/press transitions subtle (&lt;200ms); respect `prefers-reduced-motion` (future enhancement).

### A11y Do / Don't
**Do** keep a visible focus indicator on all button variants.

**Don’t** replace a disabled actionable button with a non-button element (preserve semantics) or rely solely on color to convey destructive actions.
