# Contrast Quality

<ContrastStatus />

This page centralizes the automated contrast governance for the design system.

## What The Badge Means
The badge reflects the current result of the local WCAG contrast audit across both light and dark modes:
- PASS: All required (non-informational) token pairs meet or exceed their ratio thresholds.
- FAIL: One or more required pairs fall below threshold (investigate before merging).
- INFO: One or more informational pairs were included (optional) and may not meet ratios; these do not fail CI unless explicitly enforced.

Informational pairs are intentionally unrealistic or context-dependent (e.g., accent-on-surface where that combination is never directly rendered as text/background in a real component) but tracked for visibility.

## Regenerating The Badge
```bash
npm run tokens:contrast:badge
```
Generates / updates two artifacts at repo root:
- `contrast-badge.svg` (display asset)
- `contrast-badge.json` (structured badge payload)

## Full Contrast Report
Produce a structured JSON report of every pair in all modes:
```bash
npm run tokens:contrast:json > contrast-report.json
```
Or with informational pairs expanded in terminal output:
```bash
npm run tokens:contrast:info
```

## Typical Workflow
1. Adjust primitive or semantic tokens.
2. Run `npm run tokens:check` (builds, validates, contrast checks).
3. If a contrast failure appears, tweak semantic dark overrides (preferred) or primitives (only if widely beneficial).
4. Regenerate badge if merging a meaningful change.

## CI Behavior
The GitHub Action consumes the JSON report and annotates failures. Informational pairs are excluded unless the flag `--include-informational` is added. The workflow can be extended later to comment on PRs with a diff summary.
