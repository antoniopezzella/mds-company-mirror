# Naming

Designers, developers and AI tools all use the same names for tokens,
components and properties. A name is the contract between Figma and code: if
both sides say `color/background/critical/hover`, nobody has to translate.

These principles decide every name in MDS. When a case isn't covered by the
rules further down, go back to them. They apply the system principle
[Design and code tell the same story](?path=/docs/foundations-principles--docs).

**Status.** The `--mds-*` tokens and their classes are what new code uses.
Most components still read the older `--role-*` variables (363 references
against 222 for `--mds-*` on 2026-11-03), so expect both while they're
migrated. The colour rules on this page are enforced by the token build
(`npm run tokens:figma:check`, part of `governance:ci`); four tokens are
waiting on a decision, listed under [Open naming decisions](#open-naming-decisions).

## Naming principles

### 1. One name, everywhere

**Why it matters.** Every time a name is translated (Figma to code, code to
docs, docs to an AI prompt), it can drift. Before the October taxonomy, one
colour could have four names: a Figma variable, a semantic key, a role and a
shadcn variable. Developers guessed, and Figma decisions didn't reach the code.

**What it looks like.** A token keeps the same path in Figma, the token file,
CSS and the Tailwind class. Only the separator changes. What a designer sees in
Dev Mode is exactly what a developer types.

**How we check it.** Every published token has a code name of
`var(--mds-` + its path + `)`. The token build fails if a token has no code
name, if its code name differs from its path, or if two tokens would produce
the same class.

### 2. Name the job, not the look

**Why it matters.** Values change: Dark mode, Inverse bands, a rebrand. Jobs
don't. A token called `blue` is wrong the moment Dark mode makes it light, and
V3's `Tertiary` turned out to be a grey, not a third brand colour. A name that
describes the job stays true whatever the value is.

**What it looks like.** `background/critical/subtle`, not `red-light`.
`foreground/on-media`, not `white`. Hue names live only in the hidden
primitives (`color/blue/1000`), which components never use directly.

**How to test a name.** Ask: if the value changed tomorrow, would the name still
be true? If not, rename it before it ships.

### 3. General to specific

**Why it matters.** A fixed order makes names predictable. You can guess a name
you've never seen, and autocomplete groups related tokens: type `bg-critical-`
and you see `subtle`, `hover` and `pressed` together.

**What it looks like.** What it styles → what it's for → which state or
emphasis: `color` / `background` / `primary` / `hover`. The state, if there is
one, is always the last word.

**How we check it.** The token build reads every colour token against this
order and the allowed words for each position, and fails on a word in the
wrong place.

### 4. One word, one meaning

**Why it matters.** In V3, "Active" meant four different things: pressed, on,
current and typing. Designers and developers each picked the meaning they
expected, and components behaved differently. A word that means two things
can't be documented, tested or generated by an AI tool reliably.

**What it looks like.** Closed word lists for each part of a name, and one
emphasis scale (`subtle` → `default` → `bold`). Words that caused confusion are
retired. "Active" became `Pressed` for the state, or a `Selected` or `Current`
property when it meant on or current.

**How we check it.** A retired word fails the token build, as a whole segment
or inside one (`primary-inverted`). New words are added to the lists through
the token request process
(`docs/TOKEN_REQUEST_PROCESS.md`), never ad hoc.

### 5. Safe to combine

**Why it matters.** MDS runs inside products that also use Tailwind, shadcn and
their own CSS. A name that collides gets silently overridden, and nobody notices
until something looks wrong in production.

**What it looks like.** Every public token starts with `--mds-`. Tailwind's own
names (`bg-transparent`, `p-4`) are never redefined. A component's private
variables use a short prefix of its own (`--dt-*` for the data table).

**How we check it.** The token generator stops the build if two tokens would
produce the same class.

## One name, four places

A token keeps the same path everywhere. Only the separator changes.

| Where | Form | Example |
|---|---|---|
| Figma variable | `/` path | `color/background/critical/hover` |
| Token file (DTCG) | `.` path | `color.background.critical.hover` |
| CSS custom property | `--mds-` + path with `-` | `--mds-color-background-critical-hover` |
| Tailwind class | property prefix + role + state | `bg-critical-hover` |

Dev Mode shows the CSS variable for every published token, so what you copy
from Figma exists in code.

## Design tokens

**Pattern:** `{category}/{property}/{role}/{state-or-emphasis}`

- **Category:** `color`, `space`, `size`, `radius`, `border-width`, `font`, `opacity`.
- **Property:** what the token styles (`background`, `foreground`, `border`…).
- **Role:** what it's for (`primary`, `critical`, `input`, `page`…).
- **State or emphasis:** optional last word (`default`, `hover`, `subtle`, `bold`…).
- Lowercase, words joined with `-` only inside one segment (`on-primary`, `table-row`).
- A segment is never repeated or numbered by accident: numbers are only for scales (`data/qualitative/3`, `space/16`).

## Colour

**Pattern:** `color/{property}/{role}/{state-or-emphasis}`

| Segment | Allowed words |
|---|---|
| Property | `background`, `foreground`, `border`, `overlay`, `static` (planned: `data`, and hidden `base`) |
| Role | `primary`, `secondary`, `accent`, `neutral`, `interactive`, `link`, `input`, `brand`, `avatar`, `transparent`, `critical`, `success`, `warning`, `info`, `disabled`, `selected`, `hover`, `page`, `body`, `heading`, `focus`, `section`, `translucent`, `media`, `scrim`, `on-{role}` |
| State or emphasis | `default`, `subtle`, `subtler`, `bold`, `hover`, `pressed`, `disabled`, `visited`, `placeholder` |

The role and the last word are each optional: `background/default` has no
role, `foreground/on-primary` has no last word. These lists are enforced from
`NAMING` in `scripts/tokens/generate-token-css.mjs`; change both together.

**Rules**

- **States come last:** `background/primary/default`, `background/primary/hover`, `background/primary/pressed`.
- **One emphasis scale:** `subtle` → `default` → `bold`. Not `pale`, `soft`, `strong`, `light` or `medium`.
- **Every fill has its text pair:** text on `background/critical/default` is `foreground/on-critical`.
- **Modes are not names.** Light, Dark and Inverse are modes of the same token; there is no `…-inverted` or `…-dark` token.
- **Static is for brand marks only** (`static/brand/sky`, `static/brand/midnight`). Text and icons on photos and video use `foreground/on-media`.
- **Primitives are named by hue and step** (`color/blue/1000`, `color/neutral/250`). They're hidden from pickers; components never bind them directly.

**Retired words** (the token build fails on these)

| Don't use | Use | Why |
|---|---|---|
| `active` | `pressed`, or a `Selected` / `Current` property | "Active" meant pressed, on, current and typing |
| `inverted` | the Inverse mode | A mode swap, not a second token |
| `tertiary` | `neutral` | It's a grey, not a third brand colour |
| `strong`, `pale`, `soft` | `bold`, `subtle`, `default` | One emphasis scale |
| `error`, `danger`, `informational` | `critical`, `info` | One tone vocabulary |
| `alt`, `-alpha`, `-bold` compounds | a role or leaf of its own (`translucent`, `bold`) | One idea per segment |

### Open naming decisions

Four tokens in the live export break these rules. They're listed in
`NAMING_EXCEPTIONS` so the build passes while they wait on a designer
decision. A new break fails the build. So does an entry that's been fixed but
not removed from the list.

| Token | What breaks the rule |
|---|---|
| `color/background/stripe` | `stripe` is not in the role list. Add it, or rename it (for example `background/neutral/subtler`). |
| `color/background/section/accent` | The last word `accent` is a role, not a state or emphasis. |
| `color/overlay/media/brand` | The last word `brand` is a role, not a state or emphasis. |
| `color/foreground/body/on-shell` | `on-shell` is an on-role in the last position, `shell` is no role, and the token has no code name. |

## Modes

| Figma | Code |
|---|---|
| Page in Light or Dark | `<html data-theme="light">` / `data-theme="dark"` |
| A navy band (Inverse) | `<section data-surface="inverse">` |
| A light card on a navy band | the card sets `data-surface="default"` |

- No `dark:` variants for colour. The CSS variable changes value; the class stays the same.
- During the transition `ThemeModeContext` sets both `data-theme` and the old `.dark` class. New code relies on `data-theme` only.

## Utility classes

Classes are generated from the token file by `generate-token-css.mjs`. Never write them by hand.

- **Prefix comes from the property:** `background/*` → `bg-`, `foreground/*` → `text-` (and `fill-`, `stroke-` where the token allows), `border/*` → `border-`, `overlay/*` → `bg-overlay-`, `border/focus/*` → also `ring-` and `outline-`.
- **A trailing `default` is dropped** when something is left: `background/primary/default` → `bg-primary`; `background/default` → `bg-default`.
- **No class for a job the token doesn't do:** there is no `bg-on-primary` or `border-heading`.
- **No colour literals and no opacity modifiers:** not `bg-[#000f47]`, not `bg-primary/50`. Use a token, or an `overlay/*` token for transparency.
- **Tailwind core names are never redefined.** Tailwind's own palette (`bg-red-500`) is being switched off.

## Components

**Figma**

- Component sets use plain words in sentence case: `Data table`, `Helper text`, `Side navigation`. Some existing sets are still in Title Case (`Helper Text`, `Side Navigation`) and are renamed as they're touched.
- Parts live under their parent with `/`: `Data table/Content/Text`.
- A leading `.` marks a building block you don't insert on its own (`.Field/Button`). A leading `_` marks an internal helper (`_Avatar/Overlay`). Neither is published as a main asset.

**Code**

- One component per file, file name in kebab-case: `data-grid-cells.tsx`, `button-group.tsx`.
- Exported names in PascalCase: `Button`, `ButtonGroup`, `DataGrid`.
- Story titles group by kind: `Components/Button`, `Foundations/Naming`.
- Use nouns, not verbs, and keep it to two words where you can.

## Component properties

Figma variant properties and React props use the same words. Booleans are `True` / `False` in Figma, never Yes / No or On / Off.

| Figma property | Values | React |
|---|---|---|
| `State` | Default, Hover, Pressed, Focus, Disabled | `:hover`, `:active` / `data-pressed`, `:focus-visible`, `disabled` |
| `Selected` | True / False | `selected` + `aria-selected` |
| `Checked` | True / False | `checked` |
| `Open` | True / False | `open` + `aria-expanded` |
| `Current` | True / False | `aria-current` |
| `Tone` | Neutral, Info, Success, Warning, Critical | `tone="neutral" \| "info" \| "success" \| "warning" \| "critical"` |
| `Size` | Small, Medium, Large | `size="sm" \| "md" \| "lg"` |

- **Retired values:** Active, Active/pressed, State3, Hovered, Disable, Focused, Is Checked, Expanded, Open/Close, Error, Danger, Informational.
- **Code today:** most components still use `tone="danger"` or `"default"` (36 uses of `danger` against 9 of `critical` on 2026-11-03). Those stay as deprecated aliases of `critical` and `neutral` until they're migrated (decision K8).
- **Known exceptions to "one name, everywhere":** `Size` is Small / Medium / Large in Figma but `sm` / `md` / `lg` in code, and Figma's `Neutral` tone is still `default` in code until K8 lands.

These names are agreed in principle and wait on decisions F1–F10. Until then
use the Tailwind scale described on [Spacing](?path=/docs/foundations-spacing--docs).

| Kind | Proposed Figma name | Code |
|---|---|---|
| Spacing | `space/16` (px name) | Tailwind step: `p-4` |
| Responsive spacing | `space/responsive/md` | layout utilities |
| Control height | `size/control/sm` · `md` · `lg` | `h-8` · `h-10` · `h-12` |
| Radius | `radius/none` · `xs` · `sm` · `md` · `lg` · `xl` · `full` | `--mds-radius-*` |
| Border width | `border-width/1`, `border-width/2` | `border`, `border-2` |
| Type | `font/size/14`, `typescale/body/md/size` | `--mds-font-*` |

## Component-scoped variables

- **Public tokens** are `--mds-*`. They're generated (`src/styles/generated/`); never edit them.
- **A component's own variables** use a short component prefix. The data table uses `--dt-*`, driven by the Figma DENSITY collection:

| Figma (DENSITY) | Code |
|---|---|
| `size/table-row/height` | `--dt-row-h` |
| `size/table-header/height` | `--dt-header-h` |
| `space/table-cell/inset-x` · `inset-y` | `--dt-inset-x` · `--dt-inset-y` |
| `space/table-cell/gap` · `gap-sm` | `--dt-gap` · `--dt-gap-sm` |
| `space/table-bar/inset-y` | `--dt-bar-inset-y` |

- **`--role-*` is the old hand-kept tier.** It's being replaced by `--mds-*`; don't add new roles.

## Files

- Kebab-case and lowercase for files and folders: `data-grid-format.ts`, `generate-token-css.mjs`.
- Foundations pages are `NN-Name.mdx` in `src/docs/`. The sidebar order is set by `storySort` in `.storybook/preview.tsx`, not by the number (~~"the number sets the order"~~ until 2026-11-03; it only looked that way because the sort setting wasn't being read).
