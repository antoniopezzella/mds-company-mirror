# Typography

**Two expressions. The only difference is `display` and `h1`–`h6`: face and
weight.** Body, UI copy and buttons are Noto Sans in both.

| | headings | body / UI |
|---|---|---|
| **Product** (dashboards, tools) | **Noto Sans 700** | Noto Sans 400 |
| **Marketing** (hero, long-form) | **Marsh Serif 400** | Noto Sans 400 |

## Pick a class

`text-h1` is Noto Sans. `text-serif-h1` is Marsh Serif. The **unmarked name is
the common case**, because most of what this system builds is product UI — mark
the exception, not the norm. `serif` also says what you get, where the earlier
`expressive` / `productive` naming had to be learned.

```tsx
<h1 className="text-h1">Portfolio overview</h1>        {/* product */}
<h1 className="text-serif-h1">A new chapter</h1>       {/* marketing */}
```

Both sets run `h1`–`h6`, and the serif set adds `text-serif-hero` for a
full-bleed marketing headline. The serif sizes are fluid (`clamp()`, 360–1536px);
the sans sizes are fixed Tailwind steps, because a dashboard should not reflow
its heading sizes as a window resizes.

These ship in the published package, so a consumer can write them in their own
code — verified in `dist-pkg/styles.css` rather than assumed.

## Four dashboard roles, and only four

A style earns a name **only when it bundles three or more decisions** you would
otherwise re-derive every time. Below that bar Tailwind's own class is better:
shorter, precise, and it tells you the size. `text-sm` beats a `text-data-cell`
that resolves to `text-sm` and *removes* information.

| class | resolves to | why it earns a name |
|---|---|---|
| `text-metric-value` | `text-3xl` + bold + tight tracking + tabular | nobody remembers tracking **and** tabular every time |
| `text-data-header` | `text-xs` + semibold + wide tracking + uppercase | consolidates **five** independent takes that existed in `card`, `list`, `notifications-drawer`, `stepper` and `toast` |
| `text-metric-delta` | `text-sm` + medium + tabular | |
| `text-data-numeric` | `text-sm` + tabular | the deliberate two-decision exception: `tabular-nums` is the most-forgotten decision in a data product |

Everything else uses the stock scale — `text-sm`, `font-medium`,
`tracking-wide`. That part should stay boring: developers already know it, and
designers can mirror the same names as Figma text styles.

## Guidance

- Use semantic heading levels (`<h1>`…`<h6>`) for document hierarchy, and pick
  the class by **expression**, not by element. An `<h1>` rendering at
  `text-2xl` is fine and common on dashboards.
- Line length: target 60–70ch for reading views.
- Line height: body 1.55–1.6; headings 1.1–1.45.
- Sizes are `rem`-based, so they respect the browser font-size setting
  (WCAG 1.4.4 Resize Text). A `px` scale ignores it.
- Tables: use `text-data-numeric` or add `tabular-nums`, so digits align.

## Legacy — being retired

Three mechanisms predate the classes above. They still work; **do not write new
code against them.**

**`.mds-dashboard` / `[data-typography-context='dashboard']`** — an ambient
scope on a subtree root that redefined `--typo-*` for everything inside. Three
problems, all silent: `:root` was the *marketing* expression, so a product
screen that forgot the class rendered serif headings with no error; it did not
survive a Radix portal, so `notifications-drawer` had to repeat it by hand; and
it never reached the published package at all. **Removed from every
`src/components/ui/` component on 2026-10-08** (36 reads across 23 files) and
guarded by the `typo_scope_free` metric. It remains on `PageShell` only because
~117 ad-hoc headings in app *pages* still depend on it.

**`.typography-h2` / `.typography-body1` and the `apply-variant` SCSS mixin** —
in `src/styles/_typography.scss`, used by marketing CSS Modules. Zero usage in
`src/components/ui/`.

**MUI `<Typography variant="h4">` and `sx={{ typography: 'body2' }}`** — MUI is
being removed; `src/theme.ts` still reads `--typo-*` for its 56 references.

Full migration plan and remaining steps:
`docs/tasks/typography-system.md`.
