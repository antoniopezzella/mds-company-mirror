# Typography

System typography leverages `Noto Sans` for body text and UI copy. Marketing website headings (`h1`–`h6`) and display utilities use `Marsh Serif`; dashboard containers use `Noto Sans` Bold for headings.

## Guidance
- Use semantic heading levels (`<h1>`…`<h6>`) according to document hierarchy.
- Keep display usage purposeful: marketing hero and section titles use `Marsh Serif`; dashboards use `Noto Sans` Bold for dense, scannable headings and key metrics.
- Avoid inline font overrides—add a variant to the theme if reused.
- Ensure accessible contrast and sufficient size for readability.

### When to use which variant
- h1–h3: Page and major section headings. Keep above the fold concise; avoid stacking multiple large headings.
- h4–h6: Subsections and card titles within a page.
- .typography-display: Marketing display text by default; becomes Noto Sans Bold inside `.mds-dashboard` or `[data-typography-context="dashboard"]`.
- subtitle1/2: Section descriptors, list or panel headers, supporting context.
- body1: Default reading text in dashboards and docs.
- body2: Dense UI copy: labels, secondary text, table meta (keep legible).
- caption: Tertiary metadata; avoid for persistent or critical UI text.
- overline: Short labels/chips; prefer sentence case elsewhere.

### Readability & rhythm
- Line length: target 60–70ch for reading views.
- Line height: body around 1.55–1.6; headings between 1.1–1.3.
- Numeric data: consider `font-variant-numeric: tabular-nums` in tables.

### Responsive behavior
- Sizes are clamp-based; headings shrink gracefully on small screens.
- If mobile feels heavy, reduce H1/H2 clamp mins by ~2px.

## Using typography from SCSS (source of truth)

We expose CSS variables and mixins in `src/styles/_typography.scss`. These power both CSS Modules and the MUI theme (which now reads the same variables), so React and SCSS always stay in sync.

- In a CSS Module

```scss
@use '../../styles/_typography.scss' as typo;

.cardTitle { @include typo.apply-variant(h4); }
.meta { @include typo.apply-variant(subtitle2); }
```

- With utility classes

```html
<h2 className="typography-h2">Section title</h2>
<p className="typography-body1">Body copy…</p>
```

- In MUI components (unchanged usage; now backed by CSS vars)

```tsx
<Typography variant="h4">Title</Typography>
<Box sx={{ typography: 'body2' }}>Dense label</Box>
```

Tip: Prefer variants/mixins over raw font-size declarations to keep hierarchy and responsiveness consistent.
